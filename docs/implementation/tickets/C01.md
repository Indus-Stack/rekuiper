# C01 — Freeze identities, positions, and errors

Baseline `24848c8f88363bfe0004cc88c7db73302657aa0c`.

## Interfaces

- `contracts/identity.rs` provides validated logical rule, operator, action, connection, source, partition, and position codec IDs. IDs serialize as strings with 1–128 UTF-8 bytes, beginning with a Unicode alphanumeric character or underscore and continuing with alphanumeric characters, periods, underscores, or hyphens. Connection IDs also accept the persisted `name/conf_key` format with one slash between two valid names. Identity preserves the original spelling and encoding. `DisplayName` carries a separate human-readable label. `Generation` and `CheckpointId` serialize as unsigned 64-bit integers.
- `contracts/position.rs` provides `SourcePartition`, `SourcePosition`, and `PositionCodec`. A position stores opaque cursor bytes and delegates ordering to a matching codec after checking source, partition, and ownership generation. The coordinator must complete the full contiguous message prefix, including all expanded rows, before committing progress.
- `contracts/error.rs` provides `StructuredError`, `ErrorCode`, `ErrorStage`, `ErrorObject`, and `ErrorPosition`. The code selects a fixed message. Deserialization discards incoming messages and unknown fields and emits a fixed diagnostic for invalid structured fields. Callers supply logical object identity and optional source partition, generation, and codec metadata. Opaque cursor bytes are excluded from errors.
- `contracts/mod.rs` and `lib.rs` expose the contracts through the core crate.

## Compatibility and follow-up

C01 adds opt-in typed conversions. `RuleId::try_from(&RuleDefinition)` uses the persisted rule ID. Canonical connection keys such as `mqtt/plant` and dot-form aliases such as `mqtt.plant` convert to their original spelling. Existing lookup code resolves aliases. The typed adapters reject values outside the v1 grammar and IDs longer than 128 UTF-8 bytes. A future reliable profile needs an explicit mapping to adopt those legacy values.

C02 and C03 can start after C01 is accepted. C04 owns checkpoint coordination and follows C02 and C03. Kafka codec and progress integration belong to the connector work in P03-T06.
