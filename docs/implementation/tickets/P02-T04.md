# P02-T04 — Make rate-limit buffer capacity real

- **Status:** `component_done`
- **Owners:** `crates/rekuiper-server/src/engine/operators.rs`, `crates/rekuiper-server/src/engine/dag.rs`
- **Tests:** `crates/rekuiper-server/tests/ticket_p02_t04.rs`

## Summary

- Replaced the unused `_max_buffer` field and per-caller `tokio::time::sleep` loop in `RateLimitNode` with a validated `RateLimitConfig`, `Clock`-backed token bucket (`RealClock` in production, `TestClock` in tests), and a bounded FIFO `RateLimitBuffer<T>` charged against `ResourceBudget`.
- Added explicit `RateLimitOverflowPolicy` (`DropNewest`, `DropOldest`, `Fail`) and `RateLimitConfig::validate` rejecting non-finite/non-positive `rate`, `burst < 1.0`, zero `max_buffer` or `max_buffer_bytes` for `Buffer` strategy, and unknown policy names.
- Integrated `RateLimitBuffer<StreamRecord>` into `dag.rs` using a single cancellable `wait_next_token(&cancellation)` arm in `tokio::select!`, preserving `Drop` strategy fast-path behavior and strict per-edge FIFO ordering without spawning per-item sleeping tasks.
